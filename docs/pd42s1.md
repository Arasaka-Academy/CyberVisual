# PD42S1 双轴云台

硬件链路：Jetson Nano → USB 转 RS485 → 两台 PD42S1；计划地址 1/2，115200 8N1。使用自动收发方向的 USB RS485 适配器，部署前核对实物地址、原生协议、波特率、A/B、参考地及终端电阻。软件不自动修改驱动器参数、清零硬件位置、校准编码器或执行驱动器回零。

资料存在以下不一致，不能按示例代码直接复制：

- **`2F` 使能位极性**：XLSX `驱动板->上位机` D52 写 0=失能、1=使能；手册 §4.3.16 正文写相反值，随后例子又写 0=失能。官方 STM32 的打印分支也使用相反解释。每轴 `enabled_feedback` 默认 `null`，必须在机械支撑、已确认安全使能的实物状态下核对反馈，显式填写 0 或 1。未知时不打开串口、不移动。
- **`32` 应答长度**：XLSX C58 为 45 数据字节，手册字段正文也列到 Byte45，但表头和旧例子仍写 32。实现接受 V1.2 的 45 字节布局，其他长度报告故障，不截断或猜测。
- 官方 STM32 `smd_pos_mode` 示例的数组下标/发送长度与手册及 XLSX 的 8 字节载荷不一致。实现使用手册完整十六进制例子和工作簿字段，不复制该函数的额外字节。

## 配置与启用

`network_camera.ptz_driver` 接受 `disabled`、`simulated`、`pd42s1`。依赖 `pyserial==3.5`，兼容 Python 3.6。运行账号需要串口节点权限；非 root 部署按环境加入 `dialout`，不放宽为所有用户可写。

通过配置文件或现有 `PUT /api/config` 配置 `network_camera.pd42s1`。以下为未启用运动的模板；`null` 项必须按机构与固件确认：

```json
{
  "network_camera": {
    "ptz_driver": "pd42s1",
    "pd42s1": {
      "port": "/dev/serial/by-id/实际设备",
      "baudrate": 115200,
      "pan": {
        "address": 1, "direction": 1, "counts_per_turn": 51200,
        "gear_ratio": null, "minimum_degrees": null,
        "maximum_degrees": null, "maximum_speed": null,
        "enabled_feedback": null
      },
      "tilt": {
        "address": 2, "direction": 1, "counts_per_turn": 51200,
        "gear_ratio": null, "minimum_degrees": null,
        "maximum_degrees": null, "maximum_speed": null,
        "enabled_feedback": null
      }
    }
  }
}
```

`direction` 为 ±1；`gear_ratio` 为电机转数/输出轴转数；机械范围以度为单位、相对手动中心，必须包含 0。`maximum_speed` 为输出轴度/秒。原生反馈要求 `counts_per_turn=51200`。最大速度乘传动比后必须允许 1–6000 电机 RPM；实际 RPM 向下取整、不超过配置上限。两个地址必须不同且在 1–255 内。

启动只读取参数与反馈。将两轴手动置于已确认安全的中心后，在云台面板点击“标定中心”并再次确认，或显式调用：

```http
POST /api/ptz/calibrate-center
Content-Type: application/json

{"confirm":true}
```

该操作发送零位移保持目标、确认两轴静止，再用反馈计数建立软件中心；不执行编码器校准或硬件清零。重新标定清除旧预置位。驱动重启、串口异常、异常位移或停止未确认后参考失效；手动再次确认中心才会重连并建立新参考，不自动恢复运动。

REST 与 ONVIF 共用驱动和控制器，支持方向、绝对/相对移动、停止、归位和预置位；归位返回手动中心。响应保留原字段，补充 `hardware_ready`、`calibrated`、`calibration_required`、`fault`。位置、移动和停止确认来自反馈。故障只降级云台，视频、录像与事件继续运行。

## 运动与故障边界

连续租约最长 2 秒。UI 按住时每 500 ms 续约，松开、失焦、隐藏、离线或切页发送停止。串口只有一个所有者，停止任务优先，取消待发运动并在当前事务结束后抢占；默认应答超时 150 ms、写超时 100 ms，不插断半帧。

每轴只发一个短程有限目标，确认上一目标到位后才继续；短写、校验失败或超时均不重放。剩余目标距离最多为配置速度 × 0.2 秒，量化允许一计数；进程退出或失联后不留下无限速度目标。此值限制距离，不承诺机械停止时间；低速 RPM 量化、负载和位置环误差需实测。正常退出尝试停止两轴，第一轴失败也继续第二轴；未确认则报告 `stop_unconfirmed`。

标定后持续监督反馈；超出机械范围、预期目标区间或到位超时均使参考失效。协议没有事务 ID 或可读的启动代数；超时后留出接收清空间隔并用反馈确认。无法通过相同反馈值识别的设备瞬时重启仍属于实物验收边界。

## 验证

`backend/tests/test_pd42s1.py` 覆盖中心、方向/传动比、软限位、有限目标、租约、两轴停止、异常位移和未到位目标。`backend/tests/test_pd42s1_serial.py` 覆盖官方黄金帧、分包、错地址/功能码、长度/校验/尾标志、超时、不重放、停止优先、参数只读、距离/速度边界、显式重连及真实 pyserial + Linux 伪终端 I/O。

软件测试不证明 USB 适配器线上时序、真实方向/角度、保持力、温升、拔插或进程退出运动距离。Jetson 与两台电机必须单独记录实物结果，机械参数未知时保持禁用。
